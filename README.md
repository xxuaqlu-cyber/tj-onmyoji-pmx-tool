# 阴阳师 PMX 提取与预览工具

用于从本地《阴阳师》客户端资源中提取模型，并转换为可供 MMD、Blender 等软件继续处理的 PMX 文件。工具提供带骨白模提取、材质与贴图恢复、角色附件合并、增量构建，以及按角色浏览和整理模型等功能。

## 主要功能

- **PMX 白模提取**：保留模型的骨骼、蒙皮权重与 UV，适合快速扫描全部可转换资源。
- **材质与贴图恢复**：结合资源逻辑路径、THX/THP、MaterialGroup、GIM 与 KTX 内容建立贴图对应关系。
- **主体与附件合并**：依据骨架、Bind 矩阵和空间位置验证模型关系，将确认属于同一角色的附件直接并入主体。
- **增量处理**：记录资源指纹并复用已有结果；模型移动到其他角色分类后，后续提取仍可正确判重。
- **角色化管理**：带贴图模型按角色归档，预览器可按角色筛选，并支持在右键菜单中调整分类。
- **批量预览与导出**：提供黑色背景、无光照的贴图预览，可快速移动视角、排序、分类和导出模型目录。

## 运行环境

- Windows 10 或 Windows 11（64 位）
- Python 3.10 或更高版本（64 位）
- 完整的本地游戏资源目录

程序所需的 Python 包记录在 `requirements.txt` 中。首次运行时可直接使用主界面的“安装依赖”功能，无需手动执行安装命令。

## 拉取或更新游戏资源

`拉取更新.bat` 会启动可视化资源拉取工具，通过 ADB 从 Android 模拟器或已连接设备拉取客户端数据，作为后续模型提取的 `yys` 资源来源。设备和目录信息均可在窗口中修改，不需要编辑 BAT 文件。

使用前请确认：

- 模拟器中的游戏已经完成客户端及热更新资源下载；
- 已准备可用的 `adb.exe`，或者已将 ADB 加入系统 `PATH`；
- 已开启模拟器的 ADB 调试功能。

操作步骤：

1. 启动模拟器，等待游戏资源更新完成。为避免拉取过程中资源继续变化，建议随后退出游戏或停留在不会触发下载的界面。
2. 双击 `拉取更新.bat` 打开资源拉取窗口。
3. 检查“ADB 程序”。如果程序未自动找到 ADB，点击“浏览…”选择本机的 `adb.exe`。
4. 填写模拟器的设备地址或已连接设备序列号。窗口预设了常见的 MuMu 地址，也可以点击“检测设备”从 ADB 列表中选择。
5. 检查“Android 源目录”。窗口预设了当前渠道包的数据目录；使用其他渠道包时，可直接在此处修改包名或完整远端路径。
6. 检查“本地保存目录”。默认值是项目根目录下的 `yys`，可点击“选择…”改到任意本地目录。
7. 点击“连接并检测”，确认设备可用后，再点击“开始拉取完整资源”。
8. 状态栏显示“资源拉取完成”后，启动 PMX 提取工具并选择刚才的保存目录。

窗口中的 ADB、设备、远端目录和本地目录设置会保存在本机，下次启动时自动恢复。重复拉取会更新所选目录中的资源，不需要先删除原目录。

### APK 放置位置

下载与当前游戏资源版本对应的完整 APK 后，直接将 `.apk` 文件放到项目根目录，也就是与 `启动带骨模型工具.bat`、`onmyoji_rigged_mesh_gui.py` 同一目录。APK 不需要解压，也没有强制文件名要求。

推荐目录结构：

```text
tj-onmyoji-pmx-tool/
├─ onmyoji_netease_<版本号>.apk
├─ yys/
├─ 拉取更新.bat
├─ onmyoji_resource_pull_gui.py
├─ 启动带骨模型工具.bat
├─ 启动PMX预览器.bat
└─ onmyoji_rigged_mesh_gui.py
```

随后启动工具，并选择完整的 `yys` 目录。程序会从所选目录开始，向上检查最多四级父目录中的 APK；文件名包含 `onmyoji` 或“阴阳师”的 APK 会优先使用。如果同一搜索范围存在多个候选文件，程序会选择修改时间较新的文件，因此不建议同时放置多个不同版本的 APK。

如果只选择层级较深的 `cloudfilesys3\res`，项目根目录可能超出自动搜索范围。此时可改为选择完整 `yys`，或将 APK 放到 `res` 目录及其向上四级以内的任一目录。

APK 用于补齐基础版本中的 `model.idx/model*.wpk`、THX/THP、材质 XML 和 KTX 依赖。它应尽量与当前 `yys` 资源来自同一客户端版本；版本差异可能造成材质依赖缺失或贴图候选异常。

## 快速开始

1. 下载或克隆本项目，并保持所有程序文件与 BAT 脚本位于同一目录。
2. 双击 `启动带骨模型工具.bat`。
3. 在界面中选择完整的 `yys` 游戏目录；也可以选择其中的 `cloudfilesys3\res` 目录。
4. 首次使用时点击“安装依赖”，等待安装完成。
5. 根据需要选择“一键解包 PMX 白模”或“一键解包带贴图 PMX”。
6. 处理完成后，双击 `启动PMX预览器.bat` 浏览和整理结果。

默认输出目录为项目旁的 `rigged_models`。程序只读取所选择的游戏资源，不会向游戏目录写入文件。

## 提取模式

### 一键解包 PMX 白模

该模式优先完成模型转换，不进行材质分析和贴图解码，适合快速获取全部可用模型。

处理范围包括：

- `model.idx` 与 `model*.wpk`；
- 热更新目录中的散文件；
- `temp_cache\res.zip`；
- `fx_model`、`levelsets`、`static`、`fx`、`res` 中可转换的带骨模型与静态道具。

输出位置：

```text
rigged_models/
└─ PMX白模/
   ├─ 白模清单.csv
   └─ <大小分桶>/<模型目录>/
```

每个模型目录都会生成 `.build.json` 构建记录。源资源未发生变化时，程序会复用已有 PMX，不重复转换。

### 一键解包带贴图 PMX

该模式在白模提取的基础上继续读取材质依赖，恢复能够可靠确认的贴图，并分析同一角色的分散模型。

贴图匹配以可验证的资源关系为准。当逻辑路径、材质描述和贴图实体能够互相印证时才会绑定贴图；存在歧义的结果会保留在“未匹配贴图”中，避免错误贴图覆盖模型。

确认属于同一角色的附件会在骨架兼容性、Bind 矩阵和空间位置通过验证后直接合并到主体，不另外保留“组合版”和“单独版”。

主要输出结构：

```text
rigged_models/
└─ PMX输出/
   ├─ 带贴图/
   │  └─ 按角色/<角色>/<大小分桶>/<模型目录>/
   └─ 未匹配贴图/
      └─ <大小分桶>/<模型目录>/
```

角色分类不改变模型的构建指纹。即使通过预览器将模型移动到其他角色目录，再次执行提取时也会识别并复用该结果。

## PMX 预览器

双击 `启动PMX预览器.bat` 启动。预览器以黑色背景显示贴图原色，不添加额外光照效果。

### 视图操作

| 操作 | 功能 |
| --- | --- |
| 鼠标左键拖动 | 旋转模型 |
| 鼠标右键拖动 | 平移视图 |
| 鼠标中键拖动 | 平移视图 |
| `Shift` + 鼠标左键拖动 | 平移视图 |
| 鼠标滚轮 | 缩放视图 |
| 双击预览区域 | 重置视角 |

预览列表支持按新到旧、旧到新、角色、名称和源文件大小排序，也可以先筛选角色，再连续检查该角色下的模型。

### 右键菜单

在模型列表中右键单击项目，可使用以下操作：

- **移动到其他角色分类…**：将整个模型目录移动到指定角色，并同步更新分类规则、清单和报告路径。
- **导出本模型文件夹…**：将当前模型的 PMX、贴图和构建信息完整复制到指定目录。
- **导出到上次选择目录**：连续浏览时，将多个模型快速导出到同一位置。

导出时如目标位置已有同名目录，程序会自动追加 `_2`、`_3` 等序号，不会覆盖原文件。

## 数据与缓存目录

| 目录 | 用途 | 建议 |
| --- | --- | --- |
| `yys` | 游戏资源来源 | 保持只读，无需移动到项目目录 |
| `unpacked` | WPK、材质与贴图的增量解包缓存 | 建议保留，以缩短后续处理时间 |
| `rigged_models` | PMX、贴图、报告及角色分类规则 | 可在预览器中分类和导出 |

已有的解包缓存、PMX 和 PNG 会被尽量复用。APK 的准备方式见“APK 放置位置”，已生成的 APK 内容缓存可以长期保留。

## 常见情况

### 启动脚本提示找不到 Python

安装 64 位 Python 3.10 或更高版本，并确保安装程序中的“Add Python to PATH”已启用，然后重新运行 BAT 文件。

### 界面提示缺少 Python 模块

在主工具中点击“安装依赖”，安装完成后关闭并重新启动程序。

### 模型出现在“未匹配贴图”目录

这表示当前资源中没有找到足够可靠的贴图依赖，或者存在多个无法排除的候选项。程序会保留模型与 UV，而不会强行绑定可能错误的贴图。

### 贴图看起来匹配错误

贴图错误不一定来自同一个环节，常见原因包括：

- **资源没有拉取完整**：模型已存在，但对应的 THX/THP、GIM、MaterialGroup、KTX 或热更新文件缺失，导致证据链不完整。
- **不同版本资源混用**：APK、`model.idx/model*.wpk`、THX/THP 和热更新散文件不是同一客户端版本；相同逻辑路径在不同版本中可能指向不同内容。
- **拉取时游戏仍在更新**：ADB 拉取期间源文件发生变化，最终得到一组时间点不一致的索引、模型和材质文件。
- **旧缓存与新资源并存**：中断过的解包、手动复制的缓存，或更换资源来源后继续复用旧 `unpacked`，可能留下不完整的材质关系。
- **官方资源复用或重名**：不同皮肤、展示模型、战斗模型和附件可能共用 Mesh、骨架、贴图名称或部分材质，使多个候选在文件名层面都合理。
- **材质槽信息不完整**：GIM 或 MaterialGroup 缺失时，无法可靠还原子网格与材质槽的对应顺序；多材质模型尤其容易出现局部贴错。
- **角色附件归组错误**：附件与多个角色共用骨架或贴图族时，错误的主体归属会让合并结果看起来像贴图匹配错误。
- **原游戏使用特殊着色器**：程序化材质、遮罩图、法线图、通道混合和透明效果无法仅靠 PMX 主贴图完整复现。此时贴图文件可能选对，但预览效果仍与游戏内不同。
- **贴图解码或 UV 表现异常**：ASTC/KTX 解码、透明通道或 UV 方向问题也可能呈现为花纹错位，不一定是选错了贴图文件。

排查时应先确认游戏资源已经完整更新，并保证 APK、WPK、THX/THP 与热更新文件来自同一版本。随后重新拉取资源并再次运行“带贴图 PMX”；如仍异常，记录模型目录名、PMX 材质名、被绑定的 PNG 文件和对应报告中的匹配依据。只有确认缓存来自旧版本时，才建议先备份原 `unpacked`，再重建缓存进行对照。

### 预览器异常退出

错误信息会写入项目目录下的 `pmx_preview_error.log`。保留该日志有助于定位显卡驱动、OpenGL 或模型数据问题。

## 依赖组件

- `pymeshio`：PMX 数据处理
- `Pillow`：图像处理
- `astc-encoder-py`：ASTC 贴图解码
- `cryptography`：资源数据处理
- `zstandard`：Zstandard 解压
- `numpy`：网格与矩阵计算
- `moderngl`：PMX 预览渲染
